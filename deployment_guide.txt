1. OVERVIEW & ARCHITECTURE
================================================================================

The HBL MRB system is a fully self-contained deployment:

┌─────────────────────────────────────────────────────────────────────┐
│  Browser (React SPA)                                                │
│  └──> Nginx (port 3000) ──> static files from /opt/MRB/frontend/dist│
│  └──> Direct fetch to SAP middleware (port 3002)                    │
│  └──> Self-Hosted Supabase API (port 8000) for auth, DB, realtime  │
├─────────────────────────────────────────────────────────────────────┤
│  SAP Proxy Middleware  (Node.js, port 3002)                         │
│  └──> Forwards requests to SAP RFC/BAPI endpoints                  │
│  └──> Protected by x-proxy-secret header                           │
├─────────────────────────────────────────────────────────────────────┤
│  Standalone Scheduler  (Node.js, port 3100)                         │
│  └──> Polls sap_api_config for due syncs                           │
│  └──> Uses scheduler_lock to prevent duplicates                    │
│  └──> Supports multi-plant sequential execution                    │
├─────────────────────────────────────────────────────────────────────┤
│  Self-Hosted Supabase (Docker Compose)                              │
│  └──> PostgreSQL (port 5432)                                       │
│  └──> PostgREST API (port 8001) via Kong Gateway (port 8000)       │
│  └──> Edge Functions Runtime (port 9000)                           │
│  └──> GoTrue Auth                                                  │
│  └──> Supabase Studio (port 3001) – admin dashboard                │
└─────────────────────────────────────────────────────────────────────┘

Everything is installed and configured automatically by the install script.

2. SERVER REQUIREMENTS
================================================================================

  Minimum:

    - Docker & Docker Compose (for self-hosted Supabase)

    - PM2 (process manager)

  Ports Used:

    - 3001  → Supabase Studio (admin UI)
    - 3002  → SAP Proxy Middleware
    - 3100  → Standalone Scheduler
    - 5432  → PostgreSQL (Docker)
    - 8000  → Supabase API Gateway (Kong)
    - 8001  → PostgREST
    - 9000  → Edge Functions Runtime

4. QUICK START (One-Command Install)
================================================================================

  Transfer project files to server and run:

  ┌───────────────────────────────────────────────┐
  │  sudo bash deploy/install.sh                  │
  └───────────────────────────────────────────────┘

  This single command will:
  ✓ Install system packages (Node.js, PM2, Nginx, Docker)
  ✓ Create directory structure and application user
  ✓ Copy application files
  ✓ Install & start self-hosted Supabase (Docker)
  ✓ Generate all secrets (JWT, anon key, service role key)
  ✓ Apply all 41 database migrations with tracking
  ✓ Build the React frontend
  ✓ Install middleware dependencies
  ✓ Configure Nginx with security headers
  ✓ Deploy edge functions to Supabase runtime
  ✓ Start middleware & scheduler via PM2
  ✓ Setup auto-start on boot
  ✓ Configure firewall
  ✓ Run health checks

  After install, create an admin user (see Step 8 in Section 5).

5. DETAILED INSTALLATION STEPS
================================================================================

Step 1: Transfer files to server
─────────────────────────────────
  scp -r ./project-root iml@<SERVER_IP>:/tmp/mrb-source
  # Or: git clone <repo-url> /tmp/mrb-source

Step 2: Run master installer
─────────────────────────────
  cd /tmp/mrb-source
  sudo bash deploy/install.sh

  The installer runs 13 phases automatically:
  Phase 1:  System packages
  Phase 2:  Directory structure
  Phase 3:  Copy application files
  Phase 4:  Install & start Supabase (Docker) ← NEW
  Phase 5:  Apply database migrations ← NEW
  Phase 6:  Build frontend
  Phase 7:  Middleware dependencies
  Phase 8:  Nginx configuration
  Phase 9:  Deploy edge functions ← NEW
  Phase 10: Start services (PM2)
  Phase 11: Scheduler & boot setup
  Phase 12: Firewall
  Phase 13: Health check

Step 3-7: (All automated by install.sh)

Step 8: Create admin user
─────────────────────────
  a. Access http://<SERVER_IP>:3000 and sign up with email/password
  
  b. Get your user ID:
     source /opt/MRB/.env
     psql "$SUPABASE_DB_URL" -c "SELECT user_id, email FROM profiles;"

  c. Assign admin role and plant:
     psql "$SUPABASE_DB_URL" -c \
       "INSERT INTO user_roles (user_id, role) VALUES ('<uuid>', 'admin');"
     psql "$SUPABASE_DB_URL" -c \
       "INSERT INTO user_plants (user_id, plant_code) VALUES ('<uuid>', '1300');"

Step 9: Configure Roles & Workflow
────────────────────────────────────
  After logging in as admin:
  1. Role Management → Add roles, enable workflow toggle
  2. Workflow Config → Arrange approval sequence per plant
  3. User Permission Matrix → Set module access per role

7. DATABASE SETUP & MIGRATIONS
================================================================================

Migration system features:
  - Tracking table (_migrations) prevents re-applying migrations
  - 41 migration files applied in chronological order
  - Each migration runs in a single transaction (atomic)
  - Verification of 27 tables, 15 functions, and key columns

Run manually:
  sudo bash /opt/MRB/scripts/setup-db.sh

What it does:
  1. Tests database connection
  2. Enables extensions (uuid-ossp, pgcrypto, pg_cron, pg_net)
  3. Creates _migrations tracking table
  4. Applies new migrations (skips already-applied)
  5. Verifies all 27 core tables exist
  6. Verifies 15 database functions + key schema columns
  7. Reports database stats (roles, workflows, users, MRBs)

Key tables:
  - departments         → Dynamic role definitions (role_key, workflow_status)
  - plant_workflow_config → Approval sequences per plant
  - mrb_records          → Core MRB with workflow_routing JSON
  - sap_api_config       → SAP endpoint configs
  (see Section 6 of previous guide for full list)

10. EDGE FUNCTIONS
================================================================================

5 edge functions deployed to self-hosted Supabase:

  - create-user          → Admin user creation
  - sap-sync             → SAP data synchronization
  - sap-sync-scheduler   → Scheduled SAP sync
  - seed-demo-users      → Demo data seeding
  - send-mrb-email       → Email notifications

Deployment:
  sudo bash /opt/MRB/scripts/deploy-edge-functions.sh

What it does:
  1. Discovers function source from supabase/functions/
  2. Copies to /opt/supabase/docker/volumes/functions/
  3. Generates main router (index.ts) with dynamic imports
  4. Restarts the edge functions Docker container
  5. Tests each endpoint and reports status

Edge function host access:
  Functions use host.docker.internal to reach middleware (port 3002).
  docker-compose.yml is auto-patched with extra_hosts during setup.

  │  sudo -u iml bash /opt/MRB/scripts/update.sh │
  └───────────────────────────────────────────────┘

  1. Backup current build
  2. Git pull (if repo)

  4. Apply new database migrations (tracked, no re-runs)

16. TROUBLESHOOTING
================================================================================

PROBLEM: Supabase containers not starting
  → Check: cd /opt/supabase/docker && docker compose logs
  → Fix: docker compose down && docker compose up -d
  → Verify: docker compose ps

PROBLEM: "Cannot connect to database" during setup-db.sh
  → Wait 30s for PostgreSQL container to be ready
  → Check: docker compose ps db (should show healthy)
  → Verify SUPABASE_DB_URL in /opt/MRB/.env

PROBLEM: Edge functions return 404
  → Run: sudo bash /opt/MRB/scripts/deploy-edge-functions.sh
  → Check: ls /opt/supabase/docker/volumes/functions/
  → Check: docker compose logs functions

PROBLEM: Frontend blank page
  → Check: ls /opt/MRB/frontend/dist/index.html
  → Check: nginx -t && systemctl status nginx

PROBLEM: Mixed Content errors (HTTPS → HTTP)
  → Access via http://<IP>:3000, NOT https://

PROBLEM: Migration fails
  → Check: psql "$SUPABASE_DB_URL" -c "SELECT * FROM _migrations ORDER BY applied_at;"
  → Manual apply: psql "$SUPABASE_DB_URL" -f <migration.sql> --single-transaction

PROBLEM: "host.docker.internal" unresolvable
  → Check docker-compose.yml functions service has:
    extra_hosts: ["host.docker.internal:host-gateway"]

(See previous guide sections for SAP, login, scheduler troubleshooting)

17. SECURITY CHECKLIST
================================================================================

  [ ] .env file has chmod 600 and owned by iml
  [ ] SUPABASE_SERVICE_ROLE_KEY never in frontend code
  [ ] SAP_PROXY_SECRET is strong (auto-generated)
  [ ] UFW firewall enabled (ports 22, 3000 only)
  [ ] PostgreSQL not exposed to internet (Docker internal)
  [ ] RLS policies enabled on all tables
  [ ] user_roles table separate from profiles
  [ ] Password policy: 8-10 chars, expiry 45 days
  [ ] Account lockout: 30 minutes after 5 failed attempts
  [ ] Nginx security headers configured
  [ ] Supabase Studio (3001) not exposed to internet
